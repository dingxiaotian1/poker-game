# 德州扑克（命令行 + Web 版）

一款支持 **2\~10 名玩家** 实时对战的德州扑克联机游戏，既可组建局域网房间，也可部署为**独立公网服务器**供不同网络环境的玩家连接。玩家既可以使用 **命令行客户端**，也可以用 **现代浏览器** 直接加入对局，两种客户端可同场竞技。

项目采用 **客户端-服务器（C/S）架构**：服务器承载全部权威游戏规则，客户端只负责展示与发送指令，从根本上保证各端数据一致性。全程仅使用 Python 标准库，**零第三方依赖**，开箱即用。

## 项目概述

本项目实现了一套完整的德州扑克（Texas Hold'em）游戏：

- **游戏规则完整**：底牌发放、公共牌发放（翻牌/转牌/河牌）、盲注、多轮下注、弃牌/跟注/加注/全下、手牌比较、胜负判定、边池分配，一应俱全。
- **局域网联机**：房主启动服务器，其他玩家经 TCP 连接加入，状态实时同步。
- **双端访问**：既可经**命令行**以文本命令完成全部操作，也可用**浏览器**通过 Web 界面实时对局（REST + SSE），两种客户端可同场竞技。
- **房主专属标识**：房主身份在玩家列表、座位、聊天等所有区域以专属徽章一致显示，便于快速识别房间管理者。
- **代码分层清晰**：核心逻辑（`core/`）、网络通信（`network/`）、命令行界面（`ui/`）、Web 网关（`web/`）完全解耦，便于扩展维护。

适合在宿舍、办公室等局域网环境中与朋友对战，也适合作为学习 Python 网络编程与状态机设计的参考项目。

## 核心功能

| 功能分类       | 具体能力                                             |
| ---------- | ------------------------------------------------ |
| **游戏规则**   | 完整的盲注下注轮次（翻牌前 → 翻牌 → 转牌 → 河牌 → 摊牌）               |
| **玩家行动**   | 弃牌（fold）、让牌（check）、跟注（call）、加注（raise）、全下（all-in） |
| **底池管理**   | 主池 + 边池自动分层，全下场景正确结算；平局平分（含余数分配）                 |
| **手牌评估**   | 支持全部 10 种牌型识别（高牌 → 皇家同花顺），7 选 5 最佳组合             |
| **房间管理**   | 创建房间、加入房间、房主开局、昵称去重、最多 10 人                      |
| **房间重置**   | 房主一键重置：对局数清零、筹码恢复初始值，保留玩家列表与规则（需二次确认）            |
| **实时同步**   | 状态变更即时广播，每位玩家只看到自己可见的信息（底牌隐私保护）                  |
| **断线容错**   | 玩家掉线自动弃牌并推进流程，房主离开自动转移                           |
| **自动重连**   | 网络断开后客户端指数退避自动重连，同名接管原席位，昵称不被占用                  |
| **服务器监控**  | `status` 子命令远程查看在线人数、连接数、运行时长等状态                 |
| **免安装客户端** | PyInstaller 打包为单个 exe，玩家无需 Python 与源码即可连接对局      |
| **连接管理**   | 心跳保活 + 空闲连接定时回收，连接数上限保护防止资源耗尽                    |
| **聊天交流**   | 内置聊天功能，直接输入文字即可发言                                |
| **浏览器访问**  | `web` 子命令（或 `server` 随附）启动 Web 网关，任意现代浏览器即可加入对局，支持启动/暂停/停止服务器控制 |
| **实时消息**   | Web 端 SSE 毫秒级推送，聊天消息完整显示**时间戳 + 发送者 + 内容**，可随时一键"清空"消息记录 |
| **房主专属标识** | 房主身份在玩家列表、座位、聊天等所有区域以专属徽章一致显示（CLI 与 Web 双端均支持）      |
| **低调模式**   | Web 界面一键切换为纯文本文档风格（无图形/无动画/单色灰阶），适合非工作时间低调使用     |
| **错误处理**   | 非法操作、输入校验、网络异常均有明确的命令行提示                         |
| **自动化测试**  | 122 个单元/集成测试用例，覆盖规则、协议、网络通信、部署适配与 Web 网关         |

## 技术栈说明

- **语言**：Python 3.9+
- **网络**：标准库 `socket` + `threading`（TCP 长连接，多线程并发处理）
- **数据格式**：JSON（`json` + `struct` 实现长度前缀帧协议，解决 TCP 粘包/半包）
- **界面**：标准库 `argparse`、`os`、`sys`（纯文本命令行界面，无 GUI 依赖）
- **Web 网关**：标准库 `http.server`（REST API + SSE 实时推送，静态资源托管）
- **Web 前端**：原生 HTML/CSS/JS（无框架），SSE 实现毫秒级状态同步，响应式布局 + 低调模式主题
- **测试**：标准库 `unittest`

> 项目刻意不使用任何第三方依赖，一方面降低使用门槛，另一方面避免网络层逻辑被框架遮蔽，便于学习理解。

## 使用指南

### 快速开始

本项目支持两种部署方式：**房主模式**（适合局域网）与**独立服务器模式**（适合公网部署，详见 [docs/server-deployment.md](docs/server-deployment.md)）。

**方式一：独立服务器模式（推荐公网部署，一条命令同时提供命令行 + Web 访问）**

在一台具有公网 IP 的主机上执行：

```powershell
python main.py server --port 8888 --public-ip 1.2.3.4
```

该命令**同时启动两个服务**：

| 端口                   | 用途           | 访问方式                                       |
| -------------------- | ------------ | ------------------------------------------ |
| `8888`（`--port`）     | 游戏服务器（TCP）   | 命令行客户端 `python main.py join` / `poker.exe` |
| `8000`（`--web-port`） | Web 界面（HTTP） | 浏览器打开 `http://<服务器IP>:8000`                |

玩家在任意网络环境按需选择访问方式，两种客户端可同场对局：

```powershell
# 命令行客户端：连接游戏 TCP 端口
python main.py join --host 1.2.3.4 --port 8888 --name Bob

# Web 浏览器：直接访问 Web 端口（无需安装任何软件）
# http://1.2.3.4:8000/
```

> 若只需要命令行客户端（不提供网页），启动时加 `--no-web`；Web 端口可
> 用 `--web-port` 自定义。独立 Web 网关模式（`python main.py web`）同样可用，
> 二者区别：`server` 自带交互式控制台与更多部署参数，`web` 更轻量。

服务器运行状态可通过 `status` 子命令随时远程查询（无需加入房间）：

```powershell
python main.py status --host 1.2.3.4 --port 8888
```

**方式一点五：免源码连接（打包 exe，推荐发给不装 Python 的玩家）**

若玩家电脑上**没有项目源码 / 未安装 Python**，可用 PyInstaller 将客户端打包成单个 exe 文件，直接分发运行：

```powershell
# 仅打包机需要安装 pyinstaller（游戏运行本身仍零依赖）
pip install pyinstaller

# 在项目目录执行打包
pyinstaller --onefile --console --name poker --distpath dist --workpath build --specpath build main.py
```

打包产物为 `dist/poker.exe`（约 7 MB），玩家拿到这一个文件即可：

```powershell
# 方式 A：命令行直接连接
poker.exe join --host 1.2.3.4 --port 8888 --name Bob

# 方式 B：双击运行，进入交互菜单选"加入房间"
# 方式 C：远程查看服务器状态
poker.exe status --host 1.2.3.4 --port 8888
```

> 首次运行 exe 需 1\~3 秒解压启动，属 PyInstaller 单文件特性；Windows 防火墙首次联网弹窗请选择"允许访问"。

**方式一点六：浏览器访问（Web 版）**

除命令行外，还可通过浏览器直接参与对局，无需安装任何软件：

```powershell
# 启动 Web 网关（默认 8000 端口；游戏服务器默认 8888，若已运行则自动复用）
python main.py web --web-port 8000 --game-port 8888
```

启动后，同一局域网内的玩家用浏览器打开 `http://<服务器IP>:8000` 即可：

- **实时对局**：牌桌/筹码/底池/行动区实时同步（SSE 毫秒级推送），行动按钮一键操作；
- **服务器控制**：页面顶栏提供启动 / 暂停 / 恢复 / 停止服务器按钮（管理员）；
- **房间操作**：房主可一键开始游戏 / 重置房间（带二次确认弹窗）；
- **消息分区**：右侧拆分为**"游戏日志"**与**"聊天"**两个独立子面板（视觉隔离）：日志区只显示牌局事件与系统提示，聊天区只显示玩家发言（带**时间戳 + 发送者**，房主消息带徽章），两个面板可分别点击"清空"独立清除；
- **房主专属标识**：房主座位、聊天消息、玩家列表、顶栏均带金色 `(房主)` 徽章，**对所有用户一致显示**（非仅房主本人可见）；房主离开时自动提示"房主已变更为 xxx"；
- **低调模式**：点击顶栏或加入页的"低调模式"开关，界面切换为纯文本文档风格——白底、等宽字体、单色灰阶、无图形图标、无动画，外观接近记事本/文本编辑器，适合非工作时间低调使用；偏好会保存在浏览器中，刷新后保持。

> 提示：Web 版与命令行客户端可同时连接同一游戏服务器，玩法完全一致。

**方式二：房主模式（局域网快速开局）**

**第一步：房主创建房间**

在一台电脑上执行（会打印出本机局域网 IP，供其他玩家加入）：

```powershell
python main.py host --name Alice --port 8888
```

启动成功后屏幕会显示类似提示：

```
房间已创建！其他玩家可用以下命令加入：
  python main.py join --host 192.168.1.100 --port 8888 --name <昵称>
  （若同机测试可用 127.0.0.1）
```

**第二步：其他玩家加入房间**

在局域网内其他电脑（或同一台电脑开多个终端）执行：

```powershell
python main.py join --host 192.168.1.100 --port 8888 --name Bob
```

> 其中 `192.168.1.100` 换成房主电脑实际打印出的 IP。

**第三步：开始游戏**

- 等所有玩家都加入后，**房主**输入 `/start` 开始第一局；
- 每局结束后房主再次输入 `/start` 开始下一局，庄家按钮会自动顺时针轮转。

### 界面说明

界面采用**分区设计**，游戏进度区、牌局事件区与聊天区用分隔线明确分离：

- **游戏进度区（上半部分）**：
  - 标题栏：局数 + 当前阶段（如 `[阶段: 翻牌前]`）；
  - 关键指标栏：底池、盲注、**我的筹码**、当前最高注，一目了然；
  - 公共牌、玩家列表（`D` 庄家 / `*` 当前行动者 / `<你>` 自己，当前行动者黄色高亮，**房主名字后带金色 `房主` 标记**）；
  - 你的底牌（青色加粗）与行动引导（黄色加粗的 `▶ 轮到你行动`）。
- **牌局事件区（中下部分）**：独立展示盲注/下注/摊牌等游戏事件（保留最近 40 条，界面显示最近 10 条）；
- **聊天区（下部）**：独立展示玩家发言（保留最近 30 条，界面显示最近 10 条），**房主发出的聊天附带 `(房主)` 标记**；聊天与牌局事件分区存储、互不混入，两区标题分别为 `◈ 牌局事件 ◈`（绿色）与 `◈ 聊天 ◈`（青色）。
- **快捷操作区**：固定编号菜单 + 输入提示行。
- 底牌隐私：游戏中只能看到 **自己的底牌**；摊牌阶段所有未弃牌玩家的底牌才会公开。

## 配置说明

### 命令行参数

| 参数                  | 默认值        | 说明                                                           |
| ------------------- | ---------- | ------------------------------------------------------------ |
| `--name` / `-n`     | 无（必填）      | 玩家昵称（≤ 16 字符，同房不可重复）                                         |
| `--port` / `-p`     | `8888`     | 服务器监听/连接端口                                                   |
| `--chips`           | `1000`     | 每位玩家初始筹码（仅 host/server 有效）                                   |
| `--bind`            | `0.0.0.0`  | 监听地址（仅 host/server 有效，默认监听所有网卡）                              |
| `--host`            | 无（join 必填） | 要加入的服务器 IP 地址                                                |
| `--max-connections` | `50`       | 最大同时连接数（仅 server 有效，防资源耗尽）                                   |
| `--public-ip`       | 自动探测       | 对外公告的 IP 地址（仅 host/server 有效，NAT/云环境指定公网 IP）                 |
| `--no-console`      | 开启控制台      | 关闭交互式服务器控制台（仅 server 有效，后台运行时使用）                             |
| `--web-port`        | `8000`     | server 模式随附 Web 界面的端口（仅 server 有效，浏览器访问 http\://<IP>:<port>） |
| `--no-web`          | 启动 Web     | 禁用 server 模式随附的 Web 界面（仅提供命令行客户端访问）                          |

### 网络协议

消息协议定义在 `network/protocol.py`：

- 帧格式：`[4 字节大端长度][UTF-8 JSON 载荷]`，天然解决 TCP 粘包/半包问题；
- 单条消息上限：`MAX_MESSAGE_BYTES = 256 KB`，防止异常数据撑爆内存；
- 消息类型：join/join\_ok/join\_fail、start/turn/action、hand\_over、chat/chat\_bc、reset\_req/reset\_ok/reset\_fail、error 等；
- 状态查询：`status_req` / `status_resp`（服务器监控）；
- 心跳保活：客户端每 15 秒发送 `ping`，服务器回 `pong`。

> 如需修改协议字段或消息类型，请同步维护 `protocol.py` 中 `Msg` 工厂方法与 `MSG_*` 常量，并运行测试验证。

## 常见问题解答（FAQ）

### 1. 加入房间时提示"无法连接到 ..."，怎么办？

- 确认服务器已成功启动（`python main.py status --host <IP>` 能查询成功即正常）；
- 确认 IP 与端口输入正确（以服务器公告的 IP 为准，公网环境需为公网 IP）；
- 确认两台电脑网络互通（同一局域网，或服务器已放行防火墙/安全组）；
- **检查防火墙**：Windows 防火墙可能拦截 Python，请放行 Python 或端口 `8888`（入站规则）；云服务器需在安全组放行端口。
- 完整部署步骤见 [docs/server-deployment.md](docs/server-deployment.md)。

> **【重点】先区分两种连接失败，快速定位问题**：
>
> - `[WinError 10061] 目标计算机积极拒绝` → 说明**网络与防火墙已通**（TCP 能到达服务器），但**8888 端口上没有进程在监听**。最常见原因是服务器在 SSH 终端前台运行、会话关闭后进程被终止。排查与解决：
>   ```bash
>   # ① 服务器上确认端口是否在监听
>   ss -tlnp | grep 8888
>   # ② 无输出则改用后台方式重启（关 SSH 也不退出）
>   cd /home/project/mini-game
>   nohup python main.py server --port 8888 --no-console > server.log 2>&1 &
>   # ③ 重启后验证
>   ss -tlnp | grep 8888
>   python main.py status --host 127.0.0.1 --port 8888
>   ```
> - 长时间无响应或 `[WinError 10060] 连接超时` → 说明**防火墙/安全组未放行端口**，检查入站规则是否放行 TCP `8888`（来源 `0.0.0.0/0`）。

### 2. 提示"只有房主可以开始游戏"？

独立服务器模式下**首个成功加入的玩家即为房主**。若房主离开，房主资格会自动转移给下一位玩家。输入 `/players` 可查看当前玩家。

### 3. 提示"昵称已被使用"？

同一房间内昵称不可重复，换一个昵称重新加入即可。

### 4. 提示"加注增量小于最小加注"？

加注采用"加注到目标金额"的规则：目标金额必须 ≥ 当前最高注 + 大盲注。例如当前最高注 20、大盲注 20，则至少加注到 40。**全下不受此限制**。

### 5. 为什么我看不到其他玩家的底牌？

这是**底牌隐私保护**的正常行为。德州扑克中每位玩家只能看到自己的底牌，只有进入**摊牌阶段**（打到河牌且无人弃牌）后，所有未弃牌玩家的底牌才会公开。

### 6. 同机测试时应该用什么 IP？

使用 `127.0.0.1` 即可。可以开多个终端窗口分别运行房主和玩家。

### 7. 游戏进行中突然断线会怎样？

系统会将掉线玩家自动标记为弃牌，并继续推进游戏流程，不会卡住其他玩家。房主断线后，房主资格自动转移。

**客户端会自动重连**：网络恢复后客户端以指数退避（0.5s → … → 10s）自动重连，重连成功即接管原席位，无需重新输入命令；连续 10 次重连失败才会退出。若长时间未恢复，可自行重新启动客户端加入。

### 8. 服务器上可以看到在线玩家数量吗？

可以。任意机器执行 `python main.py status --host <服务器IP>` 即可远程查看在线玩家、连接数、运行时长、当前局数等信息，无需加入房间。服务器自身也提供交互式控制台（`status` / `players` / `quit` 命令）。

### 9. 游戏报错 / 崩溃了怎么办？

- 先尝试运行测试 `python -m unittest discover -s tests` 确认环境是否正常；
- 提供**完整的报错信息**（控制台输出），在 Issue 中反馈，方便定位问题。

### 10. 浏览器打不开 Web 界面（http://IP:8000），怎么办？

先区分三种情况：

- **确认使用的是 `http://`（不是 `https://`）**：本项目 Web 网关为明文 HTTP，未配置 TLS 证书，`https://` 必然无法连接；
- **确认端口是 Web 端口 `8000`（不是游戏端口 `8888`）**：浏览器访问的是 Web 网关，`8888` 是游戏 TCP 端口，浏览器无法访问；
- **确认 Web 进程确实在运行**：`server` 模式会随附启动 Web，但若进程在前台运行、SSH 会话关闭即被终止，端口自然不通。

排查命令（在服务器上执行）：

```bash
# ① 8000 端口是否有进程监听（无输出 = Web 未启动）
ss -tlnp | grep 8000
# ② 本机自测（有返回 = Web 正常，问题在网络/防火墙）
curl http://127.0.0.1:8000/api/status
# ③ 后台方式启动（关 SSH 不退出）
cd /home/project/mini-game
nohup python main.py server --port 8888 --public-ip <公网IP> --no-console > server.log 2>&1 &
# ④ 系统防火墙放行（云服务器还需在安全组放行 8000 入站）
sudo ufw allow 8000/tcp
```

> **【重点】判断网络层是否已通**：在本地电脑执行 `Test-NetConnection <IP> -Port 8000`（PowerShell）。若 `TcpTestSucceeded` 为 True 说明端口已通、问题在浏览器端（换浏览器 / 无痕窗口 / 强制刷新）；若 8000 不通但 `8888` 通，说明 Web 进程未启动或防火墙单独拦截了 8000。
