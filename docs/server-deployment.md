# 服务器部署文档

本文档说明如何将局域网德州扑克项目部署为**独立服务器**，使玩家可以通过**服务器 IP 地址**从外部网络连接并游戏。项目全程仅使用 Python 标准库，**零第三方依赖**，可部署在 Windows / macOS / Linux 任意平台。

## 1. 架构概述

项目采用 **C/S（客户端-服务器）架构**：

```
        ┌─────────────┐
        │  服务器主机  │  ← 部署 poker 服务器（网络规则权威）
        │ main.py    │
        │ server      │  ← 监听 0.0.0.0:8888（默认）
        └──────┬──────┘
               │ TCP 长连接（JSON + 长度前缀帧协议）
      ┌────────┼────────┐
      │        │        │
 ┌────▼───┐ ┌─▼─────┐ ┌▼──────┐
 │ 玩家 A │ │ 玩家 B │ │ 玩家 C │  ← 各客户端通过服务器 IP 连接
 │ main.py│ │main.py│ │main.py│
 │ join   │ │join   │ │join   │
 └────────┘ └───────┘ └───────┘
```

- **服务器**：承载全部权威游戏规则（发牌、行动校验、底池结算），多线程并发处理多玩家连接，并定时回收失效连接。
- **客户端**：仅做显示与指令转发，通过 `join --host <服务器IP>` 连接。
- **协议**：TCP 长连接 + `[4 字节大端长度][UTF-8 JSON]` 长度前缀帧，天然解决粘包/半包。

> 与"房主模式（host）"的区别：`host` 模式服务器与房主客户端在同一进程，房主离开即房间结束；`server` 独立模式服务器常驻后台，首个连接的玩家自动成为房主，任意玩家离开不影响服务器。

## 2. 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10+ / macOS / Linux（跨平台） |
| Python | 3.9 及以上版本 |
| 第三方依赖 | **无**（仅标准库 socket / threading / json / struct） |
| 内存 | ≥ 128 MB（50 连接规模下实测峰值远低于此） |
| 网络 | 服务器需具备公网 IP（或可与客户端互通的地址） |

验证环境：

```bash
python --version          # 应输出 Python 3.9+
python -m unittest discover -s tests   # 可选：自检全部测试通过
```

## 3. 快速部署（3 分钟上手）

### 第一步：启动服务器

在服务器主机上执行：

```bash
# 默认监听 0.0.0.0:8888，开放所有网卡
python main.py server

# 指定端口 + 对外公告公网 IP（云服务器/NAT 环境推荐）
python main.py server --port 8888 --public-ip 1.2.3.4
```

启动成功后会显示监听地址与对外公告地址：

```
[INFO] 服务器已启动，监听 0.0.0.0:8888（对外地址 1.2.3.4）
[INFO] 最大连接数 50，初始筹码 1000
```

### 第二步：验证服务器可被访问

在本机或局域网内另一台机器执行：

```bash
python main.py status --host 1.2.3.4 --port 8888
```

看到"在线玩家 0/10、当前连接数 1/50、运行时长..."即表示服务器对外可访问。

### 第三步：玩家连接游戏

玩家在任意网络环境执行：

```bash
python main.py join --host 1.2.3.4 --port 8888 --name Bob
```

连接成功后，**首个玩家自动成为房主**，输入 `/start` 即可开局（需 ≥ 2 人）。

## 4. 服务器网络参数配置

支持 **命令行参数 + 环境变量** 两种配置方式，优先级为：

> **命令行参数 > 环境变量 > 程序默认值**

### 4.1 命令行参数（server 子命令）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--port` / `-p` | `8888` | 监听端口 |
| `--bind` | `0.0.0.0` | 监听地址；`0.0.0.0` 表示所有网卡 |
| `--chips` | `1000` | 每位玩家初始筹码 |
| `--max-connections` | `50` | 最大同时 TCP 连接数（防资源耗尽） |
| `--public-ip` | 自动探测 | 对外公告的 IP（NAT / 云环境手动指定公网 IP） |
| `--no-console` | 开启控制台 | 关闭交互式控制台（后台运行场景） |

### 4.2 环境变量（部署 / systemd 场景推荐）

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `POKER_PORT` | `8888` | 监听端口 |
| `POKER_BIND` | `0.0.0.0` | 监听地址 |
| `POKER_CHIPS` | `1000` | 初始筹码 |
| `POKER_MAX_CONNECTIONS` | `50` | 最大同时连接数 |
| `POKER_PUBLIC_IP` | 自动探测 | 对外公告的公网 IP |
| `POKER_CONSOLE` | `1` | 服务器控制台开关，`0` 关闭 |

示例（Linux）：

```bash
export POKER_PORT=9000
export POKER_BIND=0.0.0.0
export POKER_PUBLIC_IP=1.2.3.4
export POKER_MAX_CONNECTIONS=100
python main.py server
```

## 5. 公网访问配置

服务器默认监听 `0.0.0.0`（所有网卡），但要让外部网络客户端连接，还需放行防火墙 / 安全组 / 路由器端口。

### 5.1 防火墙放行

**Linux（ufw）**：

```bash
sudo ufw allow 8888/tcp
sudo ufw reload
```

**Linux（firewalld）**：

```bash
sudo firewall-cmd --permanent --add-port=8888/tcp
sudo firewall-cmd --reload
```

**Windows（入站规则）**：

```powershell
# 以管理员身份运行 PowerShell，放行 Python 或指定端口
New-NetFirewallRule -DisplayName "Poker Server 8888" -Direction Inbound `
  -Protocol TCP -LocalPort 8888 -Action Allow
```

### 5.2 云服务器安全组

若使用阿里云 / 腾讯云 / 华为云 / AWS 等云主机，需在**控制台安全组**中添加入站规则：

| 项目 | 值 |
|------|-----|
| 协议 | TCP |
| 端口 | `8888`（或你配置的端口） |
| 源地址 | `0.0.0.0/0`（全员可连，或限制为 CIDR 网段） |

> 修改安全组后即时生效，无需重启服务器。

### 5.3 NAT / 家用宽带 / 路由器端口映射

若服务器在**内网**（如家用电脑），需在路由器做端口映射，将公网端口转发到服务器内网 IP：

1. 确认服务器内网 IP（如 `192.168.1.100`）；
2. 登录路由器管理页（常见 `192.168.1.1`），找到 **端口映射 / 虚拟服务器 / 转发规则**；
3. 新增规则：外部端口 `8888` → 内部 IP `192.168.1.100` 端口 `8888`（TCP）；
4. 用 `--public-ip <公网IP>` 启动服务器，公告公网 IP 给玩家。

> 家用宽带公网 IP 可能动态变化，建议使用 DDNS（花生壳、阿里云解析等）绑定域名。

## 6. 后台运行与开机自启

### 6.1 Linux：nohup 后台运行

```bash
# 关闭控制台，输出日志到文件，后台运行
nohup python main.py server --port 8888 --no-console \
  > poker-server.log 2>&1 &

# 查看进程与日志
tail -f poker-server.log
ps aux | grep "main.py server"
```

### 6.2 Linux：systemd 服务（推荐）

创建 `/etc/systemd/system/poker-server.service`：

```ini
[Unit]
Description=Poker Server (Texas Hold'em)
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/mini-game
Environment=POKER_PORT=8888
Environment=POKER_PUBLIC_IP=1.2.3.4
Environment=POKER_CONSOLE=0
ExecStart=/usr/bin/python3 main.py server
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable poker-server   # 开机自启
sudo systemctl start poker-server
sudo systemctl status poker-server   # 查看状态
journalctl -u poker-server -f        # 查看日志
```

### 6.3 Windows：后台运行

```powershell
# 使用 pythonw 无窗口后台运行（日志写入 logs/poker.log，由项目自动轮转）
pythonw main.py server --port 8888 --no-console

# 开机自启：放入启动文件夹（Win+R 输入 shell:startup）
# 创建 启动服务器.bat 快捷方式，内容：
#   cd /d C:\Work\Project\mini-game
#   pythonw main.py server --port 8888 --no-console
```

> 也可注册为 Windows 计划任务（Task Scheduler），选择"登录时运行"。

## 8. 客户端连接方式

玩家通过 `join` 子命令连接，`--host` 指定服务器 IP：

```bash
python main.py join --host 1.2.3.4 --port 8888 --name Bob
```

连接特性：

- **断线自动重连**：网络波动断开后，客户端自动以指数退避（0.5s → 1s → 2s → … → 上限 10s）重连，重连成功后自动接管原席位，无需重新输入命令。
- **重连失败上限**：连续 10 次重连失败后退出，可重新启动客户端加入。
- **心跳保活**：客户端每 15 秒发送一次 ping；服务器若 45 秒未收到任何数据即判定连接死亡并回收资源。

## 9. 网络通信与可靠性机制

| 机制 | 说明 |
|------|------|
| **长度前缀帧协议** | `[4 字节大端长度][UTF-8 JSON]`，单条上限 256 KB，解决粘包/半包与内存风险 |
| **权威服务器** | 全部游戏规则在服务器执行，客户端仅转发指令，杜绝作弊与状态不一致 |
| **连接数上限** | 统计所有已接受 TCP 连接（含未加入的预连接），超限即拒绝并提示，防止资源耗尽 |
| **心跳 + 空闲回收** | 客户端 15s 心跳；服务器 reaper 线程每 10s 巡检，45s 无数据即回收连接（断网/断电/僵尸连接） |
| **重连接管** | 断线重连携带 `reconnect` 标记，同名玩家可接管旧席位；旧连接的清理与广播自动完成 |
| **掉线容错** | 玩家掉线自动弃牌推进流程，房主离开自动转移，不影响其他玩家 |
| **多线程并发** | 每连接一个读取线程，共享状态加锁串行化，保证数据一致性 |

## 10. 常见问题（FAQ）

### Q1：客户端提示"无法连接到服务器"？
- 确认服务器进程在运行（`status` 能查询成功即正常）；
- 确认 `--host` 填写的是服务器**公网 IP**（非内网 IP）；
- 检查防火墙 / 安全组是否放行对应端口（见第 5 节）；
- NAT 环境确认路由器端口映射已配置。

### Q2：服务器显示"连接数已达上限"？
- 默认上限 50，用 `--max-connections` 调大（同时关注系统文件描述符限制）；
- Linux 检查 `ulimit -n`，必要时调大。

### Q3：`--public-ip` 不设置会怎样？
- 服务器自动探测本机 IP 并公告。内网环境会公告内网 IP，公网客户端无法用它连接；
- **云服务器 / NAT 环境必须手动指定公网 IP**：`--public-ip 1.2.3.4`。

### Q4：玩家断网后重连，为什么昵称没被占用？
- 重连会携带 `reconnect` 标记，服务器识别为同一玩家接管原席位；
- 若昵称被**其他在线玩家**占用（非重连），仍会提示"昵称已被使用"。

### Q5：长时间无人操作会被踢下线吗？
- 客户端有心跳保活，正常连接不会被误判；
- 真正断网/断电的连接会在 45 秒后被服务器回收。

### Q6：如何查看服务器运行日志？
- 默认输出到控制台；后台运行时重定向到文件（nohup）或 `journalctl -u poker-server -f`（systemd）；
- 项目另有统一事件日志 `logs/poker.log`（自动轮转），记录连接/加入/断开/开局等关键事件。

## 11. 性能调优建议

- **连接数**：`POKER_MAX_CONNECTIONS` 默认 50。压力测试中 30 并发连接、10 人对局均稳定运行，一般家庭/小团队场景无需调整；大规模公网部署可调至 100+。
- **监听队列**：服务器监听队列取 `MAX_PLAYERS × 4` 与 128 的较小值（10 人同桌场景够用）。
- **并发模型**：当前为"每连接一线程"，50 连接规模下线程开销可忽略；若需支撑数百连接，可将 `network/server.py` 改造为 `selectors` 事件驱动模型（README 扩展方向已列出）。
- **网络抖动**：客户端自动重连已内置指数退避；跨公网部署时建议优先保证线路稳定，减少 NAT 会话超时导致的断连。
